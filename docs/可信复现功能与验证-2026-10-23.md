# 可信复现功能与验证

按“先接第二项目、做自动精简复现，再验证证据冲突与修复标准保护”实现。默认关闭模型，不下载权重、不调用远程推理。

## 第二个独立目标：TodoMVC

使用官方 tastejs/todomvc 提交 ff43b02e59dfa604386bb382034b2cd07c2bcd8a 的 JavaScript ES6 示例。原始源文件及哈希保存在 third_party/todomvc，服务副本在 yanzhen/web/todomvc。完整 MIT 许可一并保留，复现下载入口为 scripts/vendor_todomvc.py。

仅对服务副本调整 .js 导入、移除 webpack HMR/CSS 包导入并提供本地展示样式。模型、控制器、视图、存储的上游业务逻辑保留。上游内存存储版本标为 upstream；将存储替换为 localStorage、调整 ID 起点的本地修复版本标为 healthy。没有把对照修复归为上游代码。

支持新增、标记完成并筛选、刷新后保留三条契约。每个浏览器上下文隔离，测试数据是新建的唯一标题。原版的刷新丢失是针对这一固定示例及我们明确的持久化契约所作观察，不推断整个 TodoMVC 项目有同一问题。TodoMVC 是小型开源示例，不是完整企业系统。

## 自动精简复现

适配器提供初始动作方案，算法逐项尝试删除，并在每次删除后创建新环境重新执行。只保留仍出现同一缺陷判定的删减；缺少业务动作、缺少必要观察、前置条件失效或工具错误均不算成功复现。

- 报销系统：支持读取他人记录、重复提交已审批记录、保存后丢失三个缺陷。使用新数据库、真实 HTTP 请求，固定身份、资源归属与前置状态。这里精简的是接口动作，不是浏览器轨迹。
- TodoMVC：支持任务刷新丢失。每次用独立浏览器上下文执行真实页面操作。
- 默认最多 16 次试验，单次 20 秒；基线复现成立后进行删减，最后在两个新环境中分别确认。结论区分 verified / unstable / unconfirmed / unsupported。
- 只在给定动作集合与预算内精简，不承诺数学意义的全局最小，也没有实现任意 trace 的自动语义抽取。

每次尝试记录动作、实际观察、缺陷指纹与删减结果。内部数据库试验不占工作台历史记录；未结束内部试验纳入重启恢复。

证据包新增 reproduction.json、reproduce.py。replay.py 重放整组契约，reproduce.py <契约编号> 只运行经过验证的精简方案。两者均需要原记录仍保留和本地验真服务，尚非独立环境镜像。

## 证据冲突

通过确定性规则关联同一次检查中的证据编号：

- 报销：HTTP PATCH 返回成功，但后续 GET 的说明不等于提交值。
- TodoMVC：新增时 DOM 中存在唯一标题，但刷新后消失。

前端显示冲突原因与证据引用，完整值保留在报告中。截图、提示或单一响应均不能独立覆盖后续查询结果；没有引入未经实测的模型置信度。

## 修复标准保护

受限 ExecutionPlan 明确记录契约编号、角色、业务动作、断言、定位器、等待和跳过标记。审查只允许定位器与等待改变，拦截修改身份、断言、业务动作、契约编号和跳过检查。实际报销定位器修复调用同一审查函数，动作见证取自页面 data-action。

工作台提供四类候选的交互审查。此处是执行计划结构审查，动作见证由调用方提供，审查通过不会自动应用候选，也不能证明任意定位器的 DOM 语义等价。当前没有自动修改产品代码或执行任意模型生成脚本。

## 接口与入口

| 入口 | 用途 |
| --- | --- |
| POST /api/analyze，新增 target | 选择 reimbursement / todomvc 对应的离线语义目录 |
| POST /api/runs，target + scenario | 在目标上执行并自动精简支持的失败项 |
| GET /api/runs/{id} | 获取 conflicts、reproductions 和目标来源 |
| POST /api/runs/{id}/reproduce/{contract_id} | 用原冻结契约在新环境执行已验证的精简方案 |
| POST /api/runs/{id}/repair-review/{contract_id} | 审查受限候选计划，拒绝语义修改 |

CLI：python -m yanzhen demo --target todomvc --scenario upstream。

MCP 仍为七个工具：analyze_requirements 新增 target；replay_defects 可传 contract_id，执行精简复现。没有传 contract_id 时继续整组重放。

## 实测结果

- 45 项 pytest 测试通过：含原有框架及新增规则、负例、真实接口试验、来源哈希、无浏览器不伪造通过。
- TodoMVC 上游原版：2 项通过、1 项刷新保留失败；本地修复版：同一契约摘要下 3 项通过。
- 原始复现方案 4 步，精简后为“新增任务 → 刷新页面”2 步；两次独立确认通过。下载的 reproduce.py 已作为真实子进程运行成功。
- 证据冲突、三种错误修复拦截、合法结构修改审查、ZIP 清单校验与桌面/手机布局通过，页面脚本错误为零。
- 报销系统原有七场景的真实浏览器/接口回归及整组重放通过。

结果文件：.artifacts/innovation-check.json、evaluation.json、ui-check.json。界面截图：innovation-desktop.png、innovation-mobile.png、innovation-reduction.png。

这些结果针对两个已适配目标和有限缺陷类型，不是多项目泛化率、模型效果或比赛获奖概率。下一阶段需更复杂真实项目、独立标注集与同预算对照实验。
