# 第一版开发与验证记录

日期：2026-10-22。代码目录：D:/openjiuwen。

## 已实现

1. 中文本地工作台：需求分析、契约审阅冻结、场景选择、实时判定、证据查看、下载、重放和历史记录；支持手机布局。
2. 固定规则离线演示与 Qwen 兼容接口两种明确分开的分析方式；模型输出接受结构和来源校验，不执行模型生成的任意代码。
3. 五类检查：本人记录、他人记录限制、管理员读取、已审批记录防重复提交、保存后页面与接口一致。
4. 每次运行创建独立 SQLite 数据库，浏览器角色使用独立会话；真实 HTTP 与 Chromium 执行产生证据。
5. SHA-256 冻结契约检查、保持业务动作不变的定位器修复、产品缺陷/执行阻塞/需求不明的独立判定。
6. 脱敏 trace、截图、报告、证据包、通过新建环境重跑原契约的 replay.py。
7. 五个真实 stdio MCP 工具，附 JiuwenSwarm 配置示例。

## 验证结果

- 自动化测试：22 项通过。覆盖契约篡改、来源伪造、未知需求、模型接口模拟响应、缺少凭据不回退、三类缺陷、环境不可用、导出范围、会话脱敏、Windows 短暂文件锁、并发轮询、收尾超时和证据发布时序。
- 真实浏览器与接口回归：七个受控场景全部符合预期。正确实现与按钮改名为五项通过；三缺陷版本为两项通过、三项缺陷；三个单独缺陷版本各为四项通过、一项缺陷；服务不可用为五项阻塞。
- 三缺陷版本在新数据库中重放，冻结契约与五项判定保持一致。
- 工作台操作：生成、冻结、执行、选择证据、独立重放、历史记录、说明页均通过；桌面与 390 像素手机布局无横向溢出，未发现页面脚本错误。
- MCP：通过真实子进程握手、工具发现以及五个工具的实际调用验证。
- 实际 trace 和证据包经过扫描，未发现未替换的会话 token；数据库没有进入下载包。未完成脱敏的 trace 不提供下载，证据 ZIP 写完后才发布。

这些是内置受控场景的工程回归，不是模型能力、真实用户效果、多项目泛化或比赛名次的证明。

## 过程中修复的问题

并发回归发现，Windows 报告文件在页面轮询时可能暂时无法原子替换，导致最终状态未落盘。已增加读写锁、短暂占用重试、后台异常状态回写，并加入线程并发测试。浏览器 trace 和驱动收尾加入超时保护，避免结果完成后长时间等待关闭。
