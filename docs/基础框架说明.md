## 任务状态

正常过程为 queued → running → finalizing → completed。finalizing 表示检查已经结束，仍在收集 trace、清理浏览器和整理证据，不提前显示验收完成。

- queued / running 可请求取消，终态为 cancelled；已经完成的结果保留，未执行项不作通过或失败判定。
- finalizing 不接受用户取消，避免中断证据发布。
- 任务异常记录为 error，保留原因和已完成证据。
- 服务重启扫描全部有效历史记录，对未完成任务记录中断和结束时间；不只扫描界面最近 50 条，也不自动继续可能带副作用的操作。
- 默认最多同时执行 2 项、总共接收 8 项；本版使用单进程调度，不是分布式任务队列。

## 扩展目标

目标适配器通过代码显式注册，不从 API 参数动态导入 Python 模块。适配器要提供 key、label、supported_kinds、prepare 和 create_executor。执行器须遵循 base.py 的工具与结果协议。

引擎在创建运行前检查目标存在、契约已经冻结、目标支持全部可执行检查。prepare 失败立即记录 error，不留下无人执行的排队记录。重放继续使用原运行的 target、scenario、browser 和冻结契约。

当前只有 reimbursement 适配器。增加真实项目仍需实现账号/资源隔离、测试数据准备、检查方法和来源明确的契约，并补相应测试；现有 Contract 语义目录仍需按新的检查类型显式扩展。这个接口不代表已支持任意网站。

## 证据完整性

新证据包包含 manifest.json，记录运行编号、契约摘要、目标、场景，以及各文件的长度和 SHA-256。它能检查缺失、额外文件和内容变化；不是数字签名，也不能证明制作者身份。

ZIP 写完后原子发布，再保存 completed 状态。未脱敏的 trace 不提供下载；数据库不进入证据包。辅助截图失败会单独留下工具错误，不覆盖已经由接口证据支持的缺陷结论。

不启动服务也可以校验下载的 ZIP：

```powershell
& D:\openjiuwen\.venv\Scripts\python.exe -m yanzhen verify-evidence D:\path\evidence.zip
```

旧版证据包没有 manifest.json，仍可保留查阅，但不能声称通过新增的清单校验；新运行自动产生新格式。

## 基础接口

| 接口 | 用途 |
| --- | --- |
| GET /api/targets | 查看已注册目标及支持检查 |
| POST /api/analyze | 离线分析需求，返回待审阅契约 |
| POST /api/bundles/{id}/freeze | 按内容摘要冻结契约 |
| POST /api/runs | 入队执行 |
| GET /api/runs/{id} | 查看状态、判定与证据 |
| POST /api/runs/{id}/cancel | 请求取消排队或执行中的任务 |
| POST /api/runs/{id}/replay | 在新环境重跑原契约 |
| GET /api/runs/{id}/integrity | 校验已发布证据包 |

MCP 提供七个对应工具：需求分析、冻结、执行、报告读取、重放、取消和证据校验。它们可以独立测试，无需运行大模型。

## 当前边界

模型接口保留但默认禁用；本轮不下载模型、不做微调、不调用远程推理。当前仍以受控报销系统验证框架行为，后续重点是增加真实项目适配和对照实验。
